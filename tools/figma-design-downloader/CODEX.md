# Workflow для Codex: Figma Design Downloader

Эта инструкция применяется, когда пользователь просит скачать Figma через этот инструмент. Работай из корня целевого frontend-проекта. Не меняй приложение, package.json и настройки аккаунта. CLI расположен рядом с этим документом; разрешай его путь относительно этого файла. Используй установленный Node.js 22+ (в Codex он может быть доступен через `load_workspace_dependencies`).

1. Найди официальный подключённый Figma `download_assets` и `get_metadata`; проверь их текущие параметры. Наличие и авторизация зависят от среды. Не воспроизводи экспорт через REST. Если недоступны — сообщи об этом, не создавай ложного результата. Авторизация приложения не доступна shell-процессу; не пытайся извлечь её токены. Для переносимой установки пользователь запускает `install-codex` из README; этот документ сам по себе не является автоматически обнаруживаемым skill.
2. Выполни `node <путь>/cli.mjs parse '<URL>'`. Используй полученные fileKey и nodeId; branch key уже учтён. Не копируй tracking-параметры.
3. Если node ID указан, прочитай его `get_metadata`. Если это FRAME, извлеки id/name/width/height и экспортируй только его. Если это CANVAS/PAGE, покажи верхнеуровневые frames для выбора; не экспортируй всю страницу. Если это иной тип — попроси ссылку на frame или страницу.
4. Если ссылка на файл без node ID, вызови `get_metadata({fileKey})` без nodeId: это только список страниц. Покажи страницы для выбора. Не запрашивай содержимое всех страниц и не используй `loadAllPagesAsync`.
5. Для компактного списка frames выбранной страницы можно использовать `use_figma`. **Перед вызовом обязательно прочитай установленный навык `figma-use` и указанные им обязательные справочники.** Передавай `skillNames: "figma-use"`. Пример read-only кода ниже. Это также подходит, когда get_metadata выдаёт слишком большое дерево. Не выполняй обход вложенных frames, не меняй узлы. Покажи имена, размеры и IDs; жди выбора пользователя, если выбор не дан в исходном запросе. Не выбирай первый frame автоматически.

```javascript
const page = await figma.getNodeByIdAsync('PAGE_ID_FROM_METADATA');
if (!page || page.type !== 'PAGE') throw new Error('Page not found');
await page.loadAsync();
const frames = [];
function visit(parent) {
  for (const n of parent.children) {
    if (n.type === 'FRAME') frames.push({id:n.id,name:n.name,type:n.type,width:n.width,height:n.height});
    else if (n.type === 'SECTION') visit(n);
  }
}
visit(page);
return {page:{id:page.id,name:page.name},frames};
```

6. Для каждого выбранного frame запроси PNG в масштабе 1×: `download_assets({fileKey,nodeId,defaultFormat:"png",defaultScale:1})`. Если пользователь явно выбрал иной scale (0.01–4), передай его и затем тот же `--scale` в import. Объясни формат/масштаб до вызова, если запрос их не определяет и правила подключённого инструмента требуют явного выбора. Настройки Figma/экспортные границы могут влиять на результат: import проверит фактические пиксели, а не обещание сервера. Не вызывай get_design_context: реализация интерфейса в эту задачу не входит. Для SVG всего frame используй отдельный вызов; SVG assets включай только по запросу. Не запрашивай повторно уже доступные свежие asset URL.
7. Временный JSON-ответ (CallToolResult целиком или JSON-блок с export/rawImages/svgAssets) запиши в игнорируемый scratch-каталог `.figma-work/` или передай CLI через stdin. Не выводи секретные URL в сообщение пользователю. Metadata выбранного frame запиши отдельно:

```json
{"id":"123:456","name":"Главная","width":1920,"height":1080}
```

8. Немедленно выполни:

```text
node <путь>/cli.mjs import 'https://www.figma.com/design/FILE_KEY?node-id=123-456' --response .figma-work/export.response.json --node-info .figma-work/node-info.json --scale 1
```

Добавляй `--raw` только по запросу исходных image assets, `--svg-assets` — по запросу SVG ассетов. Не скачивай дополнительные материалы только потому, что MCP вернул их URL. По умолчанию результат — `design-reference/` в текущем проекте. `--out` допускается по запросу пользователя.

9. Удали временные response-файлы сразу после импорта штатными файловыми средствами, не трогая другие файлы. Не записывай токены/подписанные URL в репозиторий. Не изменяй .gitignore чужого проекта без необходимости; scratch должен быть за пределами Git или уже игнорироваться.
10. Проверь exit code и metadata.errors/warnings. Для PNG проверь `files[].image.width/height`, `exportScale` и `sha256` (schemaVersion 2). При несовпадении размеров не растягивай картинку и не объявляй экспорт успешным: проверь metadata, масштаб, экспортные настройки и границы Figma, затем повтори только выбранный frame при необходимости. При MCP-ошибках доступа/лимитов вызови `whoami` для диагностики. Не повторяй запросы бесконечно. При истёкшем URL обнови только выбранный frame. Сообщи количество сохранённых файлов, путь и реальные ограничения. Не называй тестовый/mock-экспорт реальным. Новый экспорт сам по себе не заменяет одобренный QA-эталон.
