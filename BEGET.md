# Запуск на Beget: инструкция для владельца

Конфигурация подготовлена, на Beget не применялась. Тип тарифа, SSH, права на процессы и подключённые сервисы неизвестны. Уточнить в панели или у поддержки: можно ли запустить постоянный ASGI-процесс Uvicorn, доступен ли reverse proxy и исходящий HTTPS к Google APIs. FastAPI требует ASGI; обычный PHP-хостинг или WSGI/Passenger сами по себе его не запускают. Если текущая услуга поддерживает ASGI, используйте её штатный запуск `api.main:app`. Пример ниже подходит для уже имеющегося VPS с systemd и Nginx, без покупки услуг.

## Требования

Python 3.12 (проверено), venv/pip, исходящий HTTPS к Google Sheets/OAuth, доверенные CA; Node >=22.12 нужен для QA, а не для сайта. Сайт — готовая статика `site/dist`, сборка не нужна. Домен и существующие сертификаты остаются под управлением владельца. Внешний адрес API — `/api/leads` на том же HTTPS-домене; браузер не получает Google-ключи.

## Локально, без Google

```sh
python3 -m venv .venv
.venv/bin/pip install -r api/requirements-test.txt
.venv/bin/python -m pytest api/tests -q
.venv/bin/uvicorn api.tests.mock_server:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000/. Формы записывают только в память. После остановки записи исчезают. Модуль `api.tests.mock_server` предназначен исключительно для локальной проверки; в размещении запускать `api.main:app`.

## Подготовка тестового размещения владельцем

1. Загрузить приложение в `/srv/veles/app`, создать пользователя `veles` и venv `/srv/veles/venv`; установить `api/requirements-lock.txt` (зафиксированные проверенные runtime-зависимости).
2. Создать **отдельную разрешённую тестовую** Google-таблицу. Включить Sheets API для service account, предоставить ему право редактора только на тестовую таблицу. Использовать её ID, не поиск по названию.
3. Сохранить ключ вне web-root: `/srv/veles/private/service-account.json`, права 600, владелец `veles`. Подготовить `/srv/veles/private/api.env` на основе `api/.env.example`. Указать абсолютный путь к ключу, тестовый `GOOGLE_SHEET_ID`, `GOOGLE_WORKSHEET=Заявки`. Не загружать эти файлы в Git, чат или публичные артефакты.
4. Для единого домена оставить `API_CORS_ORIGINS` пустым. Если фронтенд имеет другой origin, указать его полностью (`https://...`, без пути и завершающего `/`). `*` запрещён. CORS не защищает API от ботов.
5. Проверить каталог, владельца и пути в `deploy/veles-api.service`; установить service после отдельного разрешения владельца. Uvicorn слушает только 127.0.0.1:8000. Один worker сохраняет предсказуемую инициализацию листа.
6. В существующий HTTPS server-block адаптировать `deploy/nginx.conf.example`; директиву `limit_req_zone` добавить в `http`-контекст. Проверить `nginx -t` до перезагрузки. Не заменять действующую конфигурацию сайта целиком. Ограничение частоты и размера тела предусмотрено в примере Nginx.
7. `curl --fail https://TEST-DOMAIN/api/health` должен вернуть `{"ok":true}`. Это только проверка процесса, без обращения к Google.
8. После явного разрешения записи в тестовую таблицу настроить тестовый API на неё. Установить тестовые зависимости и выполнить:

```sh
GOOGLE_SERVICE_ACCOUNT_FILE=/srv/veles/private/service-account.json \
  .venv/bin/python deploy/check_test_sheet.py \
  --api-url https://TEST-DOMAIN --test-sheet-id TEST_SHEET_ID --confirm-test-write
```

Скрипт отправляет вымышленные данные и проверяет уникальную метку в колонке «Заказ» именно указанной тестовой таблицы. Сам запуск здесь **не выполнялся**. Затем отправить одну тестовую заявку через браузер и проверить строку вручную. Удаление тестовых строк — вручную владельцем.

## Контракт и эксплуатация

`POST /api/leads`, JSON: `name` (2–100), `phone` (10–15 цифр, до 30 символов), `email` (до 160), `order` (1–500), необязательные `note` (до 2000), `source` (до 40). HTTP 200 и `{"ok":true}` означают успешный ответ Sheets append. Ошибки: 422 — данные, 502 — Google/настройки, 429 — лимит Nginx. В листе семь колонок: Дата (Москва), Источник, ФИО, Телефон, Почта, Заказ, Примечание. Пустой лист получает заголовки; существующие несовместимые заголовки не перезаписываются. Значения пишутся RAW, формулы из текста не исполняются.

Фронтенд ждёт ответ до 20 секунд. После таймаута/обрыва результат может быть неизвестен: строка могла успеть записаться, повтор может создать дубль. Автоматических повторов нет. Exactly-once и идемпотентность не обещаются. Ключи, тела заявок и персональные данные не логировать; ограничить доступ к журналам и таблице. Срок хранения и текст политики обработки данных должен подтвердить владелец.

Перед production: подтвердить контакты, тексты, политику обработки данных, тарифы калькулятора и визуальную приёмку; проверить тестовую запись и восстановление после ошибки. Переключение на рабочую таблицу, запуск production, DNS и почта — отдельные согласованные действия. Для отката сохранить предыдущую статику и конфигурацию; вернуть их и перезапустить API. Изменений Mail.ru эта инструкция не требует.
